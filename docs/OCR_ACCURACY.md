## Типичные ошибки и как чиним

| Ошибка | Пример | Митигация (реализовано ✓ / план) |
|---|---|---|
| Поворот чека | 04 (снят сбоку) | ✓ OSD Tesseract + запасной word-count voting |
| Бледная термобумага | 03 | ✓ два прохода: adaptive threshold / grayscale, выбор по confidence |
| НДС/VAT принят за итог | 01, 03 | ✓ исключение строк с «VAT/MwSt/НДС/%» |
| Скидка после промежуточного итога | 07 | ✓ берём последнюю помеченную сумму, не максимум |
| Разорванные цифры/слова («4 199,00», «Tankstel le») | 01, 08 | ✓ регулярки с допуском пробелов; поиск ключевых слов по тексту без пробелов |
| Ключевые слова-корня («spar» в «sparen», «a100» в футере) | 07, 01 | ✓ слова ≥6 символов ищутся подстрокой, короткие — только целым токеном; магазин приоритетнее текста |
| Рукописные счета | 06 | ручной ввод (экран корректировки) — by design |
| Английские даты «30 MAR 13» | 03 | план: month-name mapping, низкий приоритет (целевой рынок — СНГ) |
| Латиница/кириллица вперемешку («HOC» вместо «НДС») | 01 | частично закрыто ловушкой «%»; полное решение — нормализация lookalike-символов |

## Вывод для защиты

На печатных чеках Tesseract + предобработка дают 86% точности суммы без дообучения;
экран корректировки (3–5 секунд руками) покрывает остаток — это заявленный UX.
Рукописные документы — осознанное ограничение (задача рукописного OCR — уровень
коммерческих ML-сервисов, в roadmap как перспектива).

## Датасет

Фото из Wikimedia Commons (свободные лицензии), лежат вне репозитория.
Для командного датасета (20–30 чеков) собрать свои фото: папка `backend/tests/data/receipts/`
в `.gitignore — на чеках может быть частично видна банковская карта.
